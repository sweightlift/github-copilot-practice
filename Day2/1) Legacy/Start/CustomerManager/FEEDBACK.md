## Areas to Improve

### 1. Delegation Depth — Be More Specific Upfront
Your instructions were often high-level ("proceed and test"), which works well with AI assistance but in a team setting can lead to misaligned implementations. Adding 2-3 sentences of constraints (e.g., "I want the agent on the same port, not a separate service" or "keep the frontend minimal, no complex state management") would reduce back-and-forth.

**Actionable:** Before delegating a complex task, write down 3 constraints or non-goals.

### 2. Environment Preparation
Several delays came from missing prerequisites (.NET 9 SDK, Node.js not installed, ports 3000/3001 occupied). In a production workflow, consider maintaining a `PREREQUISITES.md` or a dev container (`devcontainer.json`) so the environment is reproducible.

**Actionable:** Add a `devcontainer.json` or startup script that validates prerequisites before work begins.

### 3. Configuration / Secrets Management
The GitHub PAT is stored directly in `appsettings.json` (which could be committed). Best practice: use `appsettings.Development.json` (gitignored), user secrets (`dotnet user-secrets`), or environment variables.

**Actionable:** Move sensitive values to `dotnet user-secrets` or environment variables. Never commit API keys.

### 4. Scope Creep Awareness
The project evolved from "explore a legacy API" to a full-stack AI-powered app with a React frontend. While the learning was tremendous, in a real project this scope expansion (8→9→10→...→14 steps) without a checkpoint/review could be risky.

**Actionable:** Define "done" criteria early. Create separate branches for major features. Review scope at each milestone.

### 5. Error Investigation vs. Retry
Looking at the terminal history, there were many repeated `dotnet run` / `dotnet build` cycles with `Exit Code: 1`. Sometimes the root cause (port conflict, process still running) could be diagnosed faster by reading the error output before retrying.

**Actionable:** Adopt a "read the error → diagnose → fix → retry" habit instead of "retry → retry → force-kill → retry."
